# 5. Agent & Multi-Agent Security

*Security of LLM-based (single & multi-) agents: indirect prompt injection, tool / memory / knowledge-base poisoning, inter-agent communication attacks, agent red teaming & evaluation benchmarks, and agent-focused defenses.*

| Year | Paper | Summary | Venue | Code |
|------|-------|---------|-------|------|
| 2024 | **InjecAgent: Benchmarking Indirect Prompt Injections in Tool-Integrated LLM Agents** | **Gap:** External content processed by tool-using agents enables indirect prompt injection (IPI); no systematic benchmark existed.<br>**Method:** Benchmark that tests whether injected instructions inside external content manipulate agents into harmful tool use.<br>**Result:** Standardized, reproducible assessment of IPI risk in agentic tool-integrated systems. | ACL Findings | – |
| 2024 | **AgentDojo: A Dynamic Environment to Evaluate Prompt Injection Attacks & Defenses for LLM Agents** | **Gap:** Agent security benchmarks are static; attacks and defenses keep evolving.<br>**Method:** Extensible environment: 97 realistic tasks (email, e-banking, travel), 629 security test cases, multiple attack/defense paradigms from the literature.<br>**Result:** SOTA LLMs fail many tasks even without attacks; existing IPI attacks break some (not all) security properties. | (journal) | – |
| 2024 | **AGENTPOISON: Red-teaming LLM Agents via Poisoning Memory or Knowledge Bases** | **Gap:** Agents trust unverified memory / RAG knowledge bases.<br>**Method:** Backdoor triggers from constrained optimization mapping triggered instances into a unique embedding space → malicious demos retrieved on trigger; no model training.<br>**Result:** ≥80% ASR on driving / knowledge-QA / EHR agents with <0.1% poison rate and ≤1% benign-performance drop. | (journal) | [github](https://github.com/BillChan226/AgentPoison) |
| 2024 | **GuardAgent: Safeguard LLM Agents by a Guard Agent via Knowledge-Enabled Reasoning** ([arXiv](https://arxiv.org/abs/2406.09187)) | **Gap:** Agent safety needs guards that dynamically check whether agent actions satisfy safety requirements.<br>**Method:** GuardAgent parses safety guard requests → task plan → guardrail *code* executed deterministically; LLM reasoning + in-context memory of past experience.<br>**Result:** >98% guardrail accuracy on EICU-AC (healthcare access control), >83% on Mind2Web-SC (web safety policies). | arXiv | [page](https://guardagent.github.io/) |
| 2026 | **SafeEvolve: Harness-Policy Co-Evolution from Agent Experience for Safety Alignment** ([arXiv](https://arxiv.org/abs/2609.02786)) | **Gap:** Agent safety risk spans both final responses and multi-step trajectories; harness updates or policy optimization *alone* fail to bridge runtime control with intrinsic safety.<br>**Method:** Experience-driven self-evolving loop converting on-policy trajectory safety evidence into bounded component-level harness updates (prompts/skills) + two-stage SFT-RL policy (harness-use SFT bootstraps, harness-augmented RL shapes behavior).<br>**Result:** Stronger safety-utility tradeoff than baselines; Qwen3.5-4B achieves 3× ASR reduction on AgentDojo while benign utility rises 59.79%→61.86%. | arXiv | – |
| 2024 | **The Emerged Security and Privacy of LLM Agent: A Survey with Case Studies** | **Gap:** No comprehensive overview of newly emerged LLM-agent security & privacy issues.<br>**Method:** Survey covering agent fundamentals, threat categorization, impact on humans/environment/agents, defenses, future trends + case studies.<br>**Result:** Structured research map for LLM-agent security & privacy. | arXiv | – |
| 2025 | **Red-Teaming LLM Multi-Agent Systems via Communication Attacks (Agent-in-the-Middle, AiTM)** ([arXiv](https://arxiv.org/abs/2502.14847)) | **Gap:** Attacking inter-agent *communication* (rather than agents themselves) was unexplored.<br>**Method:** LLM-powered adversarial agent intercepts & manipulates messages between agents (reflection for context-aware malicious instructions).<br>**Result:** Compromises whole multi-agent systems across frameworks/structures/apps via message-level control alone. | arXiv | – |
| 2025 | **Attack the Messages, Not the Agents: Multi-round Adaptive Stealthy Tampering for LLM-MAS (MAST)** ([arXiv](https://arxiv.org/abs/2508.03125)) | **Gap:** Multi-agent attacks compromise agent internals or use overt persuasion — limited in stealth & adaptability.<br>**Method:** MCTS + Direct Preference Optimization to train an attack policy generating multi-round *stealthy message tampering*; dual semantic & embedding similarity constraints.<br>**Result:** High ASR with significantly better stealth than baselines across tasks, communication architectures, and LLMs. | arXiv | – |
| 2025 | **Prompt Infection: LLM-to-LLM Prompt Injection within Multi-Agent Systems** | **Gap:** Multi-agent safety research concentrates on single-agent injection; *self-replicating* LLM-to-LLM injection is a more dangerous, unstudied vector.<br>**Method:** Malicious prompts self-replicate across interconnected agents (virus-like); defense = LLM Tagging combined with existing safeguards.<br>**Result:** Multi-agent systems highly susceptible even without full communication sharing; LLM Tagging significantly mitigates spread. | (journal) | – |
| 2025 | **Les Dissonances: Cross-Tool Harvesting & Polluting in Pool-of-Tools LLM Agents (XTHP)** ([arXiv](https://arxiv.org/abs/2504.03111)) | **Gap:** Task control-flow security in multi-tool agents is unstudied.<br>**Method:** Define Cross-Tool Harvesting & Polluting (XTHP) — hijack control flow, then collect/pollute confidential info; Chord dynamic scanner detects vulnerable tools.<br>**Result:** 75% of 66 real tools from LangChain & Llama-Index are vulnerable to XTHP. | arXiv | – |
| 2025 | **Your LLM Agent Can Leak Your Data: Data Exfiltration via Backdoored Tool Use (Back-Reveal)** ([arXiv](https://arxiv.org/abs/2604.05432)) | **Gap:** Systematic data exfiltration by backdoored tool-using agents is underexplored.<br>**Method:** Embed semantic triggers by fine-tuning; on trigger the agent calls memory tools and exfiltrates user context via disguised retrieval calls.<br>**Result:** Exposes a critical exfiltration vulnerability; multi-turn interaction amplifies cumulative leakage over time. | arXiv | – |
| 2025 | **Web Fraud Attacks Against LLM-Driven Multi-Agent Systems** ([arXiv](https://arxiv.org/abs/2509.01211)) | **Gap:** Malicious Web links as a multi-agent attack vector are understudied.<br>**Method:** 12 web-fraud attack variants (homoglyph, sub-directory nesting, parameter obfuscation) exploiting how MAS trust link structures.<br>**Result:** Significant destructive potential across MAS architectures with a low attack-design threshold (no complex input design). | arXiv | [github](https://github.com/JiangYingEr/Web-Fraud-Attack-in-MAS) |
| 2025 | **Fact2Fiction: Targeted Poisoning Attack to Agentic Fact-Checking System** ([arXiv](https://arxiv.org/abs/2508.06059)) | **Gap:** Security of agentic fact-checkers (decompose→verify→aggregate) is largely unexplored; compromised checkers amplify misinformation.<br>**Method:** Mimic the decomposition strategy and exploit system-generated justifications to craft tailored malicious evidence that flips sub-claim verification.<br>**Result:** +8.9–21.2% ASR over SOTA attacks across poisoning budgets. | arXiv | – |
| 2025 | **Shadows in the Code: Risks & Defenses of LLM-based Multi-Agent Software Development (IMBIA)** ([arXiv](https://arxiv.org/abs/2511.18467)) | **Gap:** Multi-agent software-development systems have largely unexplored security risks.<br>**Method:** Two scenarios (Malicious User/Benign Agents, Benign User/Malicious Agents); Implicit Malicious Behavior Injection (IMBIA) hides malicious capability beneath benign apps; Adv-IMBIA defense.<br>**Result:** IMBIA ASR 93/45/71% (MU-BA) and 71/84/45% (BU-MA) across ChatDev/MetaGPT/AgentVerse; defense significantly reduces ASR. | arXiv | – |
| 2025 | **CORBA: Contagious Recursive Blocking Attacks on Multi-Agent Systems** | **Gap:** LLM-MAS security is unexplored beyond per-agent alignment-based refusal.<br>**Method:** CORBA uses seemingly-benign instructions that propagate contagiously across arbitrary topologies and recursively drain computational resources.<br>**Result:** Effective on AutoGen & Camel across topologies and commercial models; hard to stop via alignment. | (journal) | [github](https://github.com/zhrli324/Corba) |
| 2025 | **Agents Under Siege: Breaking Pragmatic Multi-Agent LLM Systems with Optimized Prompt Attacks** ([arXiv](https://arxiv.org/abs/2504.00218)) | **Gap:** Multi-agent attack research ignores pragmatic constraints (token bandwidth, latency, in-system defenses).<br>**Method:** Permutation-invariant adversarial attack optimizing prompt distribution over constrained network topologies (max-flow/min-cost + PIEL loss).<br>**Result:** Up to 7× better than conventional attacks; Llama-Guard & PromptGuard variants fail to block it. | arXiv | – |
| 2025 | **Automatic Red Teaming LLM-based Agents with MCP Tools (AutoMalTool)** ([arXiv](https://arxiv.org/abs/2509.21011)) | **Gap:** Red teaming MCP tool poisoning was stuck at proof-of-concept.<br>**Method:** Automated framework that generates malicious MCP tools to manipulate agent behavior.<br>**Result:** Effectively manipulates mainstream agents while evading current detection — new MCP-era risks. | arXiv | – |
| 2025 | **MCPTox: A Benchmark for Tool Poisoning Attack on Real-World MCP Servers** ([arXiv](https://arxiv.org/abs/2508.14925)) | **Gap:** Tool poisoning (malicious instructions in tool metadata, no execution) only shown via isolated cases.<br>**Method:** Systematic large-scale benchmark over real-world MCP servers.<br>**Result:** Quantifies broad tool-poisoning exposure in the MCP ecosystem. | arXiv | – |
| 2025 | **LITMUS: Benchmarking Behavioral Jailbreaks of LLM Agents in Real OS Environments** ([arXiv](https://arxiv.org/abs/2605.10779)) | **Gap:** Existing agent-safety benchmarks check only semantic output, missing physical OS-level harms and test-case contamination.<br>**Method:** Semantic–physical dual verification + OS state rollback; 819 high-risk test cases across 3 adversarial paradigms (jailbreak speaking, skill injection, entity wrapping).<br>**Result:** Frontier agents execute dangerous OS ops (Claude Sonnet 4.6: 40.64% of high-risk); reveals "Execution Hallucination" — verbal refusal after the action already completed. | arXiv | – |
| 2025 | **MultiAgentBench: Evaluating Collaboration & Competition of LLM Agents** ([arXiv](https://arxiv.org/abs/2503.01935)) | **Gap:** Benchmarks are single-agent or narrow-domain; they miss multi-agent coordination/competition dynamics.<br>**Method:** Benchmark over diverse interactive scenarios with milestone-based KPIs; evaluates star/chain/tree/graph coordination + cognitive planning.<br>**Result:** gpt-4o-mini reaches highest avg task score; graph topology best in research scenario; cognitive planning improves milestones by 3%. | arXiv | [github](https://github.com/MultiagentBench/MARBLE) |
| 2025 | **Chimera: Harnessing Multi-Agent LLMs for Automatic Insider Threat Simulation** ([arXiv](https://arxiv.org/abs/2508.07745)) | **Gap:** Insider-threat detection lacks high-quality realistic training data (real data private; synthetic data lacks semantics/realism).<br>**Method:** Multi-agent LLM framework that generates realistic, semantically rich insider-threat behavioral data.<br>**Result:** Better synthetic insider scenarios for training insider-threat detectors. | arXiv | – |
| 2026 | **MIRROR: Novelty-Constrained Memory-Guided MCTS Red-Teaming for Agentic RAG** ([arXiv](https://arxiv.org/abs/2606.26793)) | **Gap:** Agentic-RAG has a multi-surface attack surface (text/image poisoning, direct query, orchestrator tools); prior red teaming is surface-specific and recycles templates.<br>**Method:** Unified cross-surface memory-guided MCTS with an explicit novelty constraint (deterministic Novelty Gate); releases ART-SAFEBENCH.<br>**Result:** 76% ASR on image poisoning (vs 52% baseline), 97% ASR on orchestrator attacks at half the query cost, lowest cross-surface variance. | arXiv | – |
| 2026 | **CASPIAN: Online Detection & Attribution of Cascade Attacks in LLM Multi-Agent Systems** ([arXiv](https://arxiv.org/abs/2605.19240)) | **Gap:** Cascade attacks (adversarial influence propagating across agents) have distributed, cross-channel, locally-benign-looking signals — existing local/text-centric defenses miss them.<br>**Method:** Cross-channel causal monitoring: dynamic causal influence matrix + late-interaction conditional transfer entropy (LI-CTE); online attribution of origin/bridge/amplifier agents.<br>**Result:** Outperforms semantic guardrails / LLM judges / graph anomaly detectors in accuracy & early detection with <1% overhead. | arXiv | – |

| 2026 | **Honeyquest for LLMs: Rethinking Cyber Deception for AI Attackers** ([arXiv](https://arxiv.org/abs/2606.21037)) | **Gap:** Cyber-deception is designed from human-centered hypotheses; whether they transfer to AI agents is unknown.<br>**Method:** Automated evaluation (adapted Honeyquest) across 21 LLMs × 174 recon queries vs a 47-human baseline; measures trap-falling and reasoning.<br>**Result:** Every LLM falls for traps more than humans; no attention-diversion effect; 73.4% recognition-action gap (recognize trap yet exploit anyway). | arXiv | – |
