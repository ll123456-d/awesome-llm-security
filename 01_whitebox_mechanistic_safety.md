# 1. White-Box & Mechanistic Safety

*Understanding & editing safety alignment at the neuron / circuit / activation level; probing internal states for security signals.*

| Year | Paper | Summary | Venue | Code |
|------|-------|---------|-------|------|
| 2026 | **GoodVibe: Security-by-Vibe for LLM-Based Code Generation** | **Gap:** Full fine-tuning for code security is costly & prone to catastrophic forgetting; PEFT (LoRA) is coarse and limited in interpretability/control.<br>**Method:** Security reasoning localizes to a small neuron subset → find them via gradient attribution from a supervised security task, then *neuron-selective fine-tuning*; activation-driven neuron clustering cuts training cost.<br>**Result:** Up to 2.5× security gain over base (C++/Java/Swift/Go), competitive with full fine-tuning while using >4,700× fewer trainable params & >3.6× less compute than LoRA. | (code) | – |
| 2026 | **SafeNeuron: Neuron-Level Safety Alignment for LLMs** ([arXiv](https://arxiv.org/abs/2602.12158)) | **Gap:** Safety is concentrated in a small parameter subset → alignment is brittle and easily bypassed by neuron-level attacks; behavioral-level alignment gives limited control over internals.<br>**Method:** Identify safety neurons, then *freeze them during preference optimization* so the model must build redundant, distributed safety representations.<br>**Result:** Robust to neuron-pruning attacks, less repurposable as red-team generator, general ability preserved; layer-wise analysis shows safety is governed by stable, shared representations. | arXiv | – |
| 2026 | **SAGE: Signal-Amplified Guided Embeddings for LLM Vulnerability Detection** ([arXiv](https://arxiv.org/abs/2604.19031)) | **Gap:** In LLM-based vuln detection, vulnerability features are activated internally but numerically overwhelmed by dominant functional semantics ("Signal Submersion").<br>**Method:** Task-conditional Sparse Autoencoders (SAEs) isolate & amplify faint vuln signals via sparse-manifold projection (active signal recovery).<br>**Result:** Internal signal-to-noise ratio ↑12.7×; 7B model achieves up to 318% MCC gain on unseen distributions & 319% on classic sets (BigVul, PrimeVul, PreciseBugs); beats 34B baselines across 13 languages. | arXiv | – |
| 2026 | **Dissecting the Black Box: Circuit-Level Analysis of LLM Vulnerability Detection** ([arXiv](https://arxiv.org/abs/2605.29901)) | **Gap:** LLMs can detect vulnerabilities, but *how* they do it internally is a black box.<br>**Method:** Circuit Tracer on Gemma-2-2b tracing computational pathways for 472 C/C++ samples; causal ablation of identified components.<br>**Result:** Models rely mainly on *safety detectors* (attention heads recognizing safe patterns) rather than direct vuln signatures; removing Layer 11 drops accuracy 100%→6%, ablating 20 L7 neurons cuts it 50%. | arXiv | – |
| 2026 | **Which Neurons Detect Malicious Code? A Probing Study of LLM Security Knowledge** ([arXiv](https://arxiv.org/abs/2607.10221)) | **Gap:** How LLMs internally recognize malicious/vulnerable code patterns is poorly understood.<br>**Method:** Mechanistic attribution over FFN neurons in 3 instruction-tuned code LLMs (Llama3.1-8B, Mistral-7B, Qwen2.5-7B) on 1.5k+1.5k PyPI benign/malicious packages; causal intervention (amplify/suppress) validates attribution.<br>**Result:** Amplifying facilitating / suppressing inhibiting neurons boosts accuracy, reverse collapses to a single class; mechanism heavily model-dependent. Motivates neuron editing, selective unlearning, security-aware alignment. | arXiv | – |
| 2026 | **Probing the Prefill: Detecting Code Vulnerabilities via Latent Activations** ([arXiv](https://arxiv.org/abs/2608.16970)) | **Gap:** Defenses against vulnerable code output are post-hoc (static analyzers / classifiers / LLM judges) and ignore the generator's own internal state.<br>**Method:** Train small MLP probes (13.4–16M, <0.2% base size) on last-prefill-token activations of 4 frozen LLMs reading C/C++ code.<br>**Result:** 41.7% avg F1; best probe (Qwen3.5-9B) hits 68.8% F1 on Devign ≈ fine-tuned-classifier SOTA (67.9%), showing activations already carry a recoverable vuln signal. | arXiv | – |
| 2026 | **Using Mechanistic Interpretability to Craft Adversarial Attacks against LLMs** | **Gap:** Gradient-only white-box attacks ignore the internal mechanisms behind refusal; interpretability studies lack practical use.<br>**Method:** Identify *acceptance subspaces* (feature vectors that do not trigger refusal), then gradient-optimize to reroute embeddings from refusal → acceptance subspaces (jailbreak).<br>**Result:** 80–95% ASR on Gemma2 / Llama3.2 / Qwen2.5 in minutes-to-seconds vs hours for prior work. | (journal) | [github](https://github.com/Sckathach/subspace-rerouting) |
| 2026 | **Ablating Safety: Mechanisms for Removing Alignment for Security Applications** ([arXiv](https://arxiv.org/abs/2605.17413)) | **Gap:** Refusal makes authorized defensive security tasks ambiguous — is a failed answer missing capability or refusal-policy intervention?<br>**Method:** Controlled protocol comparing authorized prompting, refusal-direction projection, representation control, and task-only LoRA on SECURITY-AR (60-prompt suite).<br>**Result:** Task-only LoRA: security 0.87 / general 0.83 / unsafe-compliance 0.13, while refusal-suppression raises spillover to 0.27 → evaluate alignment removal as a utility-risk frontier, not an uncensoring recipe. | arXiv | – |
| 2026 | **Willing but Unable: Separating Refusal from Capability in Code LLMs via Abliteration** ([arXiv](https://arxiv.org/abs/2606.05396)) | **Gap:** Building labeled-vulnerable-code datasets requires instructing aligned code LLMs to inject a specified CWE, but they systematically refuse such prompts.<br>**Method:** Abliteration (low-rank weight edit removing refusal direction) on Qwen2.5-Coder 3B/7B/14B; CWE-89 (SQLi) case study on PromSec/SafeCoder; verdicts by CodeQL+Semgrep+Bandit ensemble.<br>**Result:** Refusal →0 across sizes while syntactic validity >93%; injection rate stays capacity-bound (14B 88–97%, 7B 89–90%, 3B 25–48%) — abliteration unlocks *willingness*, capability still scales with parameters. | arXiv | – |
| 2026 | **Not All Refusals Are Equal: How Safety Alignment Fails Cybersecurity at Scale** ([arXiv](https://arxiv.org/abs/2607.02714)) | **Gap:** Safety alignment doesn't distinguish domains/harm levels, blocking legitimate authorized cyber operations.<br>**Method:** Large-scale abliteration on 24 open-source LLMs incl. 1T-param Kimi K2, isolating the *cybersecurity-only* harmful subspace across layers (esp. MoE).<br>**Result:** Domain-specific abliteration is achievable; safety-training type & architecture are the most reliable predictors; 3 susceptibility tiers proposed. | arXiv | – |
| 2026 | **Robust Harmful Features Under Jailbreak Attacks (Attention-Head Specialization)** ([arXiv](https://arxiv.org/abs/2606.28153)) | **Gap:** Mechanism of jailbreaks unclear; assumption that attacks eliminate safety features entirely is wrong.<br>**Method:** Show attacks *selectively suppress* early-layer Adversarially-Compromised Heads (ACHs), while mid-layer Safety-Aligned Heads (SAHs) stay robust ("Robust Harmful Features"); use persistent activations for training-free detection.<br>**Result:** Suppressing few ACHs induces jailbreak-like behavior; reading SAH activations gives competitive detection with strong adversarial robustness. | arXiv | – |
| 2026 | **CSULoRA: Closest Safe Update Low-Rank Adaptation** ([arXiv](https://arxiv.org/abs/2605.30640)) | **Gap:** Small amounts of unsafe fine-tuning data weaken aligned LoRA models; hard interventions (projection/pruning) discard task-relevant info.<br>**Method:** Post-hoc correction estimating a safety-aligned subspace from aligned-vs-base weight displacement; decompose each LoRA update and solve a closed-form min-change problem that smoothly attenuates unsafe directions by energy.<br>**Result:** Substantially reduces ASR while preserving most LoRA utility gains. | arXiv | – |
| 2026 | **Do LLMs Know Their Vulnerable Scenarios?** ([arXiv](https://arxiv.org/abs/2607.23496)) | **Gap:** Why embedding harmful requests in certain scenarios bypasses refusal is mechanistically unexplained.<br>**Method:** Show scenario-wrapped prompts activate internal scenario directions whose causal steering reduces refusal; **Concept2Scenario** attributes refusal-suppression to SAE concepts → interpretable NL scenarios + interaction attribution.<br>**Result:** Discovered scenarios raise ASR by up to 18.2 pp & transfer to GPT-5, Claude-Haiku-4.5, Gemini-3-Flash (shared refusal vulnerabilities across families). | arXiv | – |
| 2026 | **A Granular Study of Safety Pretraining under Model Abliteration** ([arXiv](https://arxiv.org/abs/2510.02768)) | **Gap:** Do safety interventions (refusal/metatag training) survive simple inference-time activation edits like abliteration?<br>**Method:** Controlled evaluation across SmolLM2-1.7B Safety-Pretraining checkpoints + baselines; 20 systems × 100 prompts, multi-judge REFUSAL/NON-REFUSAL classification.<br>**Result:** Checkpoint-level map of which data-centric safety components remain robust under abliteration; judge choice measurably biases evaluation. | arXiv | [github](https://github.com/shashankskagnihotri/safety_pretraining) |
| 2026 | **NeuroStrike: Neuron-Level Attacks on Aligned LLMs** ([arXiv](https://arxiv.org/abs/2509.11864)) | **Gap:** Prompt-based jailbreaks rely on trial & error, lack cross-model generalizability, and are limited in scalability/reliability.<br>**Method:** Attack at the neuron level by manipulating the internal neurons responsible for safety in aligned LLMs.<br>**Result:** Bypasses alignment across models more reliably and scalably than prompt-space attacks. | NDSS | – |
| 2025 | **Tongue-Tied: Breaking LLM Safety Through New Language Learning** | **Gap:** Safety is language-dependent; low-resource languages & code-switching already show weak safety coverage.<br>**Method:** LoRA-finetune LLMs on a low-resource language (Newari) + two *fabricated* fake languages using only **non-harmful** data.<br>**Result:** Learning a new language alone (no harmful content) jailbreaks safety — fine-tuning objectives override safety even with benign data. | CALCS | – |
| 2026 | **Jailbreak to Protect: Buffering and Reinforcing via Temporary Jailbreaking for Safe Fine-Tuning** ([arXiv](https://arxiv.org/abs/2605.24550)) | **Gap:** Fine-tuning-as-a-Service weakens alignment under harmful-FT attacks; why temp-jailbreak defenses work is unclear.<br>**Method:** Gradient analysis shows temporary jailbreaking *saturates safety-degrading gradients* while keeping benign ones; BufferLoRA (removable jailbreak adapter) buffers updates, ReinforceLoRA (QR-merge) restores refusal.<br>**Result:** Superior safety + utility, no extra safety data during user FT, minimal compute. | arXiv | – |
| 2025 | **Watch Your Steps: Dormant Adversarial Behaviors that Activate upon LLM Finetuning (FAB)** ([arXiv](https://arxiv.org/abs/2505.16567)) | **Gap:** Fine-tuning is treated as a controlled, secure process; adversarial behavior is assumed to need an attacker at inference.<br>**Method:** Meta-learning attack that compromises an LLM to be benign now but activate adversarial behaviors (ads, jailbreakability, over-refusal) once downstream users fine-tune it.<br>**Result:** FAB triggers robust across datasets / steps / schedulers / post-training — challenges the security of fine-tuning. | arXiv | – |
| 2025 | **No, Of Course I Can! Deeper Fine-Tuning Attacks That Bypass Token-Level Safety Mechanisms** ([arXiv](https://arxiv.org/abs/2502.19537)) | **Gap:** Existing fine-tuning attacks are shallow — they target only the first response tokens, so generating them with an aligned model blocks the attack.<br>**Method:** *Refuse-then-comply*: train models to first refuse harmful requests, then answer them — bypassing shallow defenses & output filters.<br>**Result:** ASR 57% on GPT-4o and 72% on Claude Haiku; $2000 OpenAI bug bounty; undermines "refuses → safe" reasoning. | arXiv | – |
| 2024 | **Weak-to-Strong Jailbreaking on Large Language Models** ([arXiv](https://arxiv.org/abs/2401.17256)) | **Gap:** Existing jailbreaks are computationally costly (iterative optimization).<br>**Method:** Jailbroken & aligned models differ mainly in *initial decoding distribution* → use two small models (safe + unsafe) to adversarially steer a larger safe model's decoding in one pass.<br>**Result:** Misalignment >99% on two datasets with a single forward pass per example. | arXiv | [github](https://github.com/XuandongZhao/weak-to-strong) |
| 2024 | **BadLlama: Cheaply Removing Safety Fine-Tuning from Llama 2-Chat 13B** ([arXiv](https://arxiv.org/abs/2311.00117)) | **Gap:** Public weight release lets bad actors cheaply strip safeguards.<br>**Method:** Demonstrate low-cost fine-tuning to undo safety fine-tuning while retaining general capabilities.<br>**Result:** Removes Llama 2-Chat 13B safety fine-tuning for <$200; argues for caution in releasing weights of future, more capable models. | arXiv | – |
| 2023 | **Fine-tuning Aligned Language Models Compromises Safety, Even When Users Do Not Intend To!** ([arXiv](https://arxiv.org/abs/2310.03693)) | **Gap:** Safety alignment covers inference-time but not end-user fine-tuning privileges.<br>**Method:** Red-team via OpenAI API fine-tuning on few adversarial examples; also test benign/standard datasets.<br>**Result:** Jailbreaks GPT-3.5 Turbo on just 10 examples (<$0.20); even benign fine-tuning degrades safety alignment. | arXiv | – |
| 2023 | **Shadow Alignment: The Ease of Subverting Safely-Aligned Language Models** ([arXiv](https://arxiv.org/abs/2310.02949)) | **Gap:** Prior focus on hard-prompt attacks; subversion via fine-tuning with tiny data is overlooked.<br>**Method:** Fine-tune on ~100 malicious examples in 1 GPU hour ("Shadow Alignment") to elicit harmful tasks without losing helpfulness.<br>**Result:** Subverts 8 models from 5 orgs; transfers to multi-turn dialogue and other languages. | arXiv | – |
| 2026 | **Safety Mirage: Spurious Correlations Undermine VLM Safety Fine-Tuning** ([arXiv](https://arxiv.org/abs/2503.11832)) | **Gap:** Supervised safety fine-tuning learns spurious text-surface correlations rather than intrinsic harm mitigation → fails on 1-word edits & over-refuses benign queries.<br>**Method:** Machine unlearning (MU) as an alignment alternative that directly removes harmful knowledge without biased feature-label maps.<br>**Result:** MU-based alignment cuts ASR by up to 60.27% and unnecessary rejections by >84.2%. | arXiv | [github](https://github.com/OPTML-Group/VLM-Safety-Unlearn) |
| 2026 | **Fewer Weights, More Problems: A Practical Attack on LLM Pruning** ([arXiv](https://arxiv.org/abs/2510.07985)) | **Gap:** LLM pruning is widely used at deployment (vLLM), but its security implications are underexplored.<br>**Method:** An adversary estimates pruning likelihood per parameter, injects malicious behavior into *unlikely-to-be-pruned* weights, then uses likely-pruned weights to cancel it — so the unpruned model looks benign but becomes malicious after pruning.<br>**Result:** After Magnitude/Wanda/SparseGPT pruning, attack succeeds across scenarios (up to 95.7% jailbreak, 98.7% refusal of benign instructions, 99.5% targeted content injection) on 5 models. | arXiv | – |
| 2026 | **Adaptive Probe-based Steering for Robust LLM Jailbreaking** ([arXiv](https://arxiv.org/abs/2605.20286)) | **Gap:** Contrastive-steering jailbreaks rely on limited/biased contrastive prompts and laborious manual steering-strength tuning.<br>**Method:** Use model extraction to guide steering vectors toward an ideal one; tune steering strength adaptively from contrastive-activation statistics.<br>**Result:** Notably improves effectiveness & robustness of probe-based steering with no extra prompts or manual tuning (avg harmfulness 6%→70%). | arXiv | [github](https://github.com/fhdnskfbeuv/adaptiveSteering) |
| 2026 | **Backdoors in RLVR: Jailbreak Backdoors in LLMs From Verifiable Reward** ([arXiv](https://arxiv.org/abs/2604.09748)) | **Gap:** RL with Verifiable Rewards (RLVR) boosts reasoning but its *training-set* backdoor vulnerability was unidentified.<br>**Method:** Asymmetric Chain Backdoor (ACB): inject <2% poisoned data — high positive reward for harmful responses, negative for refusals — implanting a backdoor without modifying the verifier.<br>**Result:** Backdoor implanted across scales with no benign-task drop; activating the trigger degrades safety by avg 73% on jailbreak benchmarks; generalizes across jailbreak methods. | arXiv | [github](https://github.com/yuki-younai/Backdoor_in_RLVR) |
