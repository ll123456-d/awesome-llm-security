# 6. LLM-Driven Offensive Security

*Using LLMs / LLM agents to attack real systems: penetration testing, vulnerability discovery, exploit generation, malware & ransomware, and offense-oriented benchmarks.*

| Year | Paper | Summary | Venue | Code |
|------|-------|---------|-------|------|
| 2026 | **Can LLMs Hack Enterprise Networks? Autonomous Assumed-Breach Penetration Testing of Active Directory** ([arXiv](https://arxiv.org/abs/2502.04227)) | **Gap:** Enterprise pentesting is costly and scarce in human expertise.<br>**Method:** Autonomous LLM-driven prototype performing *Assumed-Breach* pentests against a real Microsoft AD testbed (GOAD); evaluated on 5 LLMs.<br>**Result:** LLMs can dynamically adapt attack strategies, run inter-context attacks (web/social/credential), self-correct; costs competitive with human pentesters. | TOSEM | – |
| 2025 | **Teams of LLM Agents can Exploit Zero-Day Vulnerabilities** ([arXiv](https://arxiv.org/abs/2406.01637)) | **Gap:** LLM agents exploit described vulns + toy CTFs but perform poorly on real *unknown* (zero-day) vulns.<br>**Method:** Hierarchical multi-agent team (team lead / commander / agent) applied to real-world zero-day vulnerabilities.<br>**Result:** First demonstration of an agent team exploiting real, previously-unknown vulnerabilities. | arXiv | – |
| 2025 | **Incalmo: An Autonomous LLM-assisted System for Red Teaming Multi-Host Networks** | **Gap:** Realistic multi-host ("stepping stone") red-team exercises are expensive & expertise-heavy; SOTA LLM offense systems can't run them.<br>**Method:** Autonomous LLM-assisted system planning/executing multi-host network attacks.<br>**Result:** Executes multi-host red-team campaigns that PentestGPT / CyberSecEval-style systems cannot. | arXiv | – |
| 2025 | **Ransomware 3.0: Self-Composing and LLM-Orchestrated** ([arXiv](https://arxiv.org/abs/2508.20444)) | **Gap:** First threat model for LLM-orchestrated ransomware; malware that dynamically synthesizes itself.<br>**Method:** Prototype embedding NL prompts in the binary; LLM synthesizes polymorphic malicious code at runtime, adapts to environment, runs closed-loop recon/payload/extortion.<br>**Result:** Open-source LLMs generate functional ransomware components & sustain closed-loop execution across personal/enterprise/embedded environments; provides behavioral signals for defense. | arXiv | – |
| 2025 | **Towards Effective Offensive Security LLM Agents: Hyperparameter Tuning, LLM-as-a-Judge, and a Lightweight CTF Benchmark (CTFTiny / CTFJudge)** ([arXiv](https://arxiv.org/abs/2508.05674)) | **Gap:** What drives offensive-security agent success is not systematically understood.<br>**Method:** CTFJudge (LLM-as-judge trajectory eval), CCI metric for partial correctness, hyperparameter study, and CTFTiny benchmark (50 CTF challenges).<br>**Result:** Identifies optimal multi-agent coordination & hyperparameter settings; releases CTFTiny + CTFJudge. | arXiv | [github](https://github.com/NYU-LLM-CTF/CTFTiny) |
| 2026 | **Decoupling Reconnaissance and Exploitation: Measuring Capability Boundaries of LLM-Based Web Pentesting** | **Gap:** End-to-end black-box eval of pentest agents suffers error cascading (early recon failures mask exploitation ability).<br>**Method:** Two-stage decoupled evaluation (exploit vs recon) with ground-truth injection & knowledge ablation over 70 high-fidelity web-vuln testbeds; 5 open-source agents.<br>**Result:** With accurate context, functional success up to 90%; autonomous recon recall plateaus ~50%, mainly due to parsing unstructured telemetry; architecture niches identified. | (journal) | – |
