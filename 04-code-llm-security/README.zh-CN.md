# 4. 代码大模型安全（Code-LLM Security）

**[English](README.md) | [中文](README.zh-CN.md)** · [返回总目录](../README.zh-CN.md)

*针对代码生成 / 编码智能体的攻击（恶意代码越狱、提示脆弱性），以及对编码助手（"vibe coding"）不安全代码的度量。*

| 年份 | 论文 | 摘要（出发点 / 方法 / 结果） | 发表 | 代码 |
|------|------|------|------|------|
| 2025 | **施放 SPELL：面向突破 LLM 限制的句子配对探索** ([arXiv](https://arxiv.org/abs/2512.21236)) | **出发点：** 越狱研究针对通用 LLM；*恶意代码生成*作为越狱目标未被充分探索。<br>**方法：** SPELL 测试框架用时分复用选择策略，从先验知识数据集智能组合句子（探索新颖 / 利用成功攻击模式）。<br>**结果：** 8 类恶意代码上 GPT-4.1 / Claude-3.5 / Qwen2.5-Coder 成功率分别为 83.75% / 19.38% / 68.12%；超 73% 输出被 SOTA 检测器确认恶意。 | arXiv | – |
| 2026 | **语法约束解码可诱使 LLM 生成恶意代码（CodeSpear）** ([arXiv](https://arxiv.org/abs/2606.11817)) | **出发点：** 语法约束解码（GCD）本用于保证语法有效性、被视为安全；其安全风险未被研究。<br>**方法：** 证明仅施加*良性*代码语法约束本身即可越狱 LLM，使其输出恶意代码。<br>**结果：** GCD 成为恶意代码生成的、反直觉的新攻击面。 | arXiv | – |
| 2026 | **MultiCodeAttack：基于多代码提示注入的迭代越狱攻击** | **出发点：** 结构化代码模板越狱多为固定模板、单语言；跨语言与自适应进化未被探索。<br>**方法：** 维护多语言模板库；用多臂老虎机选择高攻击性语言；用语义保持、响应感知变异进化模板。<br>**结果：** 有害文本生成较基线高 28.23%–832.59%，恶意代码输出最多多 136.22%（覆盖 8–11 个 LLM）。 | (期刊) | [匿名](https://anonymous.4open.science/r/MultiCodeAttack/) |
| 2026 | **Vibe Coding 安全吗？真实任务中智能体生成代码的漏洞基准（SUSVIBES）** ([arXiv](https://arxiv.org/abs/2512.03262)) | **出发点：** vibe coding（低监督的智能体编码）日益普及，但其生成代码是否安全未知。<br>**方法：** 基准含 186 个真实世界特性请求任务（人类程序员曾提交带漏洞实现）；评估 12 种前沿编码智能体配置。<br>**结果：** 智能体安全表现糟糕：SWE-Agent+Claude 4 Sonnet 功能正确率 57%、安全率仅 11.8%；附加漏洞提示也无法缓解。 | arXiv | [github](https://github.com/LeiLiLab/susvibes) |
| 2026 | **极小的提示扰动即致代码漏洞：提示脆弱性与隐藏状态信号** ([arXiv](https://arxiv.org/abs/2605.29737)) | **出发点：** 已有工作显示提示变异破坏功能正确性；是否也破坏*安全性*此前未被研究。<br>**方法：** 对 3 个模型 × 5 种语言做 token 级提示变异；探测隐藏状态以判断能否在生成前预测。<br>**结果：** 单字符改动即可让代码由安全翻转为易受攻击；输入处理类漏洞更可预测（AUC 0.753），安全默认值类较差（AUC 0.674）——前者可在生成前捕获，后者需解码时干预。 | arXiv | – |
